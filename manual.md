## Что такое Git

**Git** — это распределённая система контроля версий, созданная Линусом Торвальдсом в 2005 году. Она используется для отслеживания изменений в коде и совместной работы над проектами. Каждый разработчик имеет полную копию репозитория, что делает систему устойчивой и быстрой.

Git помогает:
- сохранять историю изменений проекта;
- работать в команде над одним кодом без конфликтов;
- быстро откатываться к прошлым версиям;
- создавать независимые ветки для новых функций и исправлений;
- синхронизировать локальную работу с удалёнными репозиториями (GitHub, GitLab и др.).
## Основные понятия

|Термин|Описание|
|---|---|
|**Repository (repo)**|Хранилище проекта, где Git отслеживает изменения файлов и истории|
|**Commit**|Снимок текущего состояния проекта с описанием изменений|
|**Branch**|Ветка разработки — независимая линия работы над кодом|
|**Merge**|Объединение изменений из одной ветки в другую|
|**Remote**|Удалённый репозиторий, например, на GitHub|
|**Staging area**|Промежуточная область, где подготавливаются файлы перед коммитом|
|**HEAD**|Указатель на текущий коммит или ветку|
## Настройка Git

Перед использованием Git настройте информацию о себе, которая будет отображаться в коммитах:

```bash
git config --global user.name "Ваше имя"
git config --global user.email "email@example.com"
git config --global core.editor "code --wait"  # Настроить редактор по умолчанию
git config --list                              # Проверить текущие настройки
```

Если нужно задать настройки только для конкретного проекта — уберите флаг `--global`.
## Создание и инициализация репозитория

Новый локальный репозиторий создаётся так:

```bash
git init
```

Это создаст скрытую папку `.git`, где Git будет хранить историю и метаданные проекта. Если вы уже клонируете репозиторий с сервера, то делать `init` не нужно.

Чтобы проверить структуру проекта, можно ввести:

```bash
ls -a
```

Вы увидите скрытую папку `.git` — признак того, что проект отслеживается.
## Клонирование существующего репозитория

Если проект уже размещён в сети (например, на GitHub), вы можете получить его копию:

```bash
git clone <url>
```

Можно клонировать определённую ветку:

```bash
git clone -b <branch> <url>
```

> 💡 Пример: `git clone -b develop https://github.com/user/project.git`


## Проверка состояния проекта

Команда `git status` показывает текущие изменения, которые ещё не добавлены в коммит.

```bash
git status
```

Типичные состояния файлов:
- **untracked** — новые файлы, не добавленные в Git;
- **modified** — изменённые, но не подготовленные файлы;
- **staged** — подготовленные к коммиту файлы.

Чтобы добавить файл в staging area:

```bash
git add <файл>
```

Или сразу все:

```bash
git add .
```

Если хотите убрать файл из staging:

```bash
git restore --staged <файл>
```

## Коммиты

Коммит — это ключевая единица истории Git. Каждый коммит содержит:

- метаданные (автор, дата);
- сообщение с описанием изменений;
- хеш — уникальный идентификатор.

Пример создания коммита:

```bash
git commit -m "Добавил новую функцию расчёта скидки"
```

Если вы хотите добавить и закоммитить отслеживаемые файлы сразу:

```bash
git commit -am "Исправил баг с логикой фильтрации"
```

Историю можно посмотреть так:

```bash
git log
```

Для компактного отображения:

```bash
git log --oneline --graph --decorate --all
```
## Работа с ветками

Ветки позволяют работать над несколькими задачами параллельно, не мешая основной версии проекта.

Создание новой ветки и переход в неё:

```bash
git checkout -b feature/new-ui
```

Посмотреть список веток:

```bash
git branch
```

Слияние ветки с текущей:

```bash
git merge feature/new-ui
```

Удаление ветки после слияния:

```bash
git branch -d feature/new-ui
```

## Работа с удалёнными репозиториями

Добавление удалённого репозитория:

```bash
git remote add origin <url>
```

Отправка изменений на сервер:

```bash
git push -u origin main
```

Получение изменений с сервера:

```bash
git pull
```

> ⚠️ `git pull` сочетает в себе `fetch` + `merge`. Чтобы только скачать обновления без слияния, используйте `git fetch`.



## Откат изменений и исправления

Иногда нужно отменить коммит или вернуть прошлое состояние файлов:

```bash
git reset --soft HEAD~1    # Удалить последний коммит, оставить изменения в staging
git reset --hard HEAD~1    # Полностью отменить последний коммит
```

Для безопасного отката без потери истории используйте `revert`:

```bash
git revert <commit_hash>
```

Чтобы увидеть разницу между версиями:

```bash
git diff                 # Изменения после последнего коммита
git diff --staged        # Изменения, добавленные в staging
```

## Временное сохранение изменений

Если нужно быстро переключиться на другую ветку, не теряя текущие изменения:

```bash
git stash                # Сохранить изменения во временное хранилище
git stash list           # Просмотреть список сохранений
git stash pop            # Вернуть последние изменения
```

## Теги и релизы

Теги используют для обозначения версий проекта:

```bash
git tag v1.0.0
```

Чтобы отправить теги на сервер:

```bash
git push origin --tags
```

## Полезные приёмы

- `git blame <файл>` — кто и когда изменил каждую строку.
- `git show <commit>` — показать детали конкретного коммита.
- `git reflog` — история всех перемещений HEAD (поможет восстановить утерянный коммит).
- `git clean -fd` — удалить неотслеживаемые файлы и папки.

## Типичный рабочий процесс (workflow)

1. Клонируем проект:
```bash
git clone <url>
```

2. Создаём новую ветку для задачи:
```bash
git checkout -b feature/new-functionality
```

3. Вносим изменения и проверяем статус:
```bash
git status
```

4. Добавляем файлы:
```bash
git add .
```

5. Коммитим:
```bash
git commit -m "Добавил новую функциональность"
```

6. Отправляем ветку на сервер:
```bash
git push origin feature/new-functionality
```

7. После ревью объединяем в основную ветку
